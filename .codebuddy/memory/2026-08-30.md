## 客户端「点击生成后结果图不显示」排查（PM 亲带）
- 现象：用户在前端（frontend-react）点「开始试穿」后，提示生成成功，但**结果图不显示（破图/一直转圈/空白）**。
- 先排除后端：真实触发 `/tryon/generate/`，后端用 `uuid.uuid4().hex` 生成 result_url（例 `/static/uploads/results/708300cfb5724bf2a57629a8688378c4.png`，**无 `-`**），文件真实落盘；经前端 5173 代理访问返回 `200 / image/png / 5274 字节`。**后端与资源 100% 正常**。
- 排除 URL 处理：前端 `getMediaUrl`/`getFileUrl` 对无 `-` 的 `/static/uploads/...` 路径原样返回（`getFileUrl` 第 507 行 `includes('-') && length>30` 的 uuid 误判只对带 `-` 的串生效，result_url 不触发）；`resultUrl` prop 链（useTryOn→App→MainStage→PreviewCanvas）全部正确；选服装 UI 已浏览器实跑验证正常。
- **根因定位（前端渲染层）**：结果图经 `CachedImage` 渲染，组件默认 `lazy=true`：初始 `inView=false` → 返回占位 spinner div、`<img>` 根本不渲染；靠 `IntersectionObserver` 监听 `imgRef.current` 进入视口才 `setInView(true)` 渲染 `<img>`。但 `inView=false` 时渲染的是**占位 div（ref=imgRef）**，observer 观察的是这个 div；`setInView(true)` 后重渲染成 `<img ref={imgRef}>`（新元素），旧 div 已卸载 → **observer 观察目标丢失**，结果图在生成完成后的动态布局中 `<img>` 永不渲染 → 表现即「生成成功但结果图一直转圈/空白」。
- **修复**（低风险、精准）：
  1. `frontend-react/src/components/sections/PreviewCanvas.jsx`：结果图 `<CachedImage>` 加 `lazy={false}`——用户主动生成的关键结果图本就该立即加载，绕过懒加载 observer 不确定性。
  2. `frontend-react/src/components/CachedImage.jsx`：observer 观察目标从 `imgRef.current`（随占位/真图切换而丢失）改为**稳定的 `wrapperRef`**（占位返回与真实 img 共用同一 wrapper），消除 div→img 的 ref 切换 race，根治其他图片场景的同类隐患。
- 验证：`npm run build` 86 模块零错误；主页面 `playwright_navigate` 加载正常、无白屏/报错；lint 零错误。
- 限制说明：本环境 Playwright MCP 的 `upload_file` 对隐藏的 `<input type=file>` 等待 visible 超时、且 `evaluate` 不在本项目执行函数体，故无法自动化「上传形象→点生成」的端到端点击复现；但后端资源、URL 处理、prop 链、构建均已逐项验证，修复逻辑经代码审查确认有效，请用户在浏览器实测结果图是否正常显示。
