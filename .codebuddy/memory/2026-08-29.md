## 修复用户反馈的 3 个交互问题（扫码形象不更新 / 生成报错无提示 / 请求报错无业务提示）
### 问题1：扫码上传完个人形象没有更新
- 根因：`AvatarSection` 轮询成功后只调 `onSetAvatarPreview(imageUrl)`，**没回传 image_key**；而 `App.handleTryOn` 仅在 `avatarSource==='system'` 时读 `REUSE_AVATAR_KEY`，导致扫码形象只能走「把预览图 fetch 下来再重新上传一遍」的兜底路径，且来源/复用 key 都没落库。
- 修复：
  - `AvatarSection.startPolling`：`onSetAvatarPreview?.(res.data.image_url, res.data.image_key)`（后端 status 接口本就返回 image_key，此前未使用）。
  - `App.jsx` onSetAvatarPreview 支持第二参 imageKey → 写入 `REUSE_AVATAR_KEY` + `REUSE_AVATAR_SOURCE='user'` + `setAvatarSource('user')`。
  - `handleTryOn`：新增 `canReuseStoredKey`（有 storedKey 且 source 为 system 或 user）→ 直接复用 key，避免重复上传同一张图。
### 问题2：生成报错但前端没有任何提示
- 根因：`useTryOn.pollStatus` 的 `if (response.success) {...}` **没有 else 分支**。当 status 接口返回 404/500 时什么都不做，轮询静默停止 → 界面永久卡在「生成中」，无任何提示。
- 修复：补 else 分支 —— 404 立即 fail（任务不存在）；超 deadline 用后端错误文案 fail；其余错误 3s 后继续轮询。fail 前调 `api.markHandled(response)` 去重。
### 问题3：前端请求后端报错都没有业务提示
- 根因两层：
  1. 后端**无全局异常处理器**，未捕获异常只返回 `Internal Server Error`（无 `content-type: application/json` 时前端还会退化成「服务器返回非预期格式」）。
  2. 前端大量调用点只写 `if (response.success)`，else 静默。
- 修复：
  - `backend/app/main.py` 新增三个 `@app.exception_handler`：
    - `RequestValidationError` → 422，把错误转成「字段名: 原因」中文可读提示，并 warn 日志。
    - `HTTPException` → 统一结构 `{detail, message, error_code}`（保留 headers，兼容 401 WWW-Authenticate）。
    - `Exception` → 500，记录完整堆栈到 logger，debug/开发环境回传真实错误，生产返回「服务器开小差了，请稍后重试」。
  - `frontend-react/src/utils/request.js` 新增**未消费错误自动提示**机制：
    - `setGlobalErrorHandler(fn)` + `markHandled(response)` + `scheduleErrorReport(result)`。
    - 失败时延后一个宏任务再提示；若调用方已自行处理（调 markHandled）则跳过 → 既保证被遗忘的失败必有反馈，又不与调用方提示重复。
    - `api.markHandled` 挂到 api 对象上；网络错误分支也接入。
  - `App.jsx`：useEffect 注册全局 handler → showToast（401 跳过，由认证流程统一处理）。
  - `useTryOn.submitTask` 自行提示处调 `api.markHandled(response)` 去重。
