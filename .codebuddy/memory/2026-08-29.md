## 配置 CodeBuddy Hooks（提升效率与质量）
- 规范来源：Hooks 兼容 Claude Code Hooks 规范，27+ 事件。配置存 `<项目>/.codebuddy/settings.json`（项目级，可共享）或 `~/.codebuddy/settings.json`（用户级）。
- **重要**：直接编辑 settings.json 不会立即生效，需在 IDE 的 `/hooks` 面板审核后才应用。
- 落地 4 个钩子（均本地快速执行，无 LLM 开销），脚本在 `.codebuddy/hooks/`：
  1. `session_context.py`（SessionStart，matcher=startup）：注入项目约定——venv 在根目录、后端须从 `backend/` 启动才加载 `backend/.env`、三端端口、测试账号、**模型主键是 `id` 而非 `uuid`（仅 FileRecord 有 uuid 业务字段）**、存储走本地 `/static/uploads`、`upload_file` 返回二元组、`TryOnRecord.status` 是 int。
  2. `guard_command.py`（PreToolUse，matcher=Bash|execute_command）：deny 危险命令（rm -rf /、mkfs、dd、fork bomb、强推主分支等）；ask 破坏性但合法命令（**`docker compose down -v` 会删数据卷丢数据库**、DROP DATABASE、TRUNCATE、git reset --hard、git clean -fd 等）。
  3. `check_python.py`（PostToolUse，matcher=Write|Edit）：改动 backend 下 .py 后跑 `py_compile` 即时报语法错误；若改动的是 `app/models/` 下模型文件，提醒同步排查 api/schemas/services 的所有引用（针对性防范本项目「模型改字段→路由引用旧字段→500」的历史根因）。
  4. `trim_output.py`（PostToolUse，matcher=Bash）：命令输出超 6000 字符才截断（留头 3500 + 尾 1500），否则原样放行，节省上下文 token。
- 已验证：settings.json JSON 有效；4 个脚本用 echo 管道灌入样例输入均返回预期 JSON（deny / ask / 静默 / 截断 / 语法报错 / 模型提醒）；lint 0 错误；测试临时文件已清理。
- 工具名说明：matcher 支持双向别名（CLI 风格 `Write/Bash` 与 IDE 风格 `write_to_file/execute_command` 可互配），脚本内取值已兼容 `file_path`/`filePath` 等多种键名并全程 try/except 兜底（钩子故障绝不阻塞主流程）。
- 可选增强（未启用，因每次 Stop 调 LLM 会变慢）：Stop 事件配 `type: "prompt"` 质量门禁，让模型在收尾前自检是否跑过测试/lint；或用内置 `/goal <条件>` 实现「持续工作直到条件满足」。
