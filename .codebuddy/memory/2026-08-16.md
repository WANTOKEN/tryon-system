## 修复：启动报错 Access denied for user 'tryon'@'192.168.65.1'（MySQL 认证失败）
- 根因不是 MySQL 用户本身，而是**配置未加载**：用户的 venv 在项目根 /Users/apple/my_project（.venv 在此），从根目录运行 uvicorn 时 cwd 是根；而 config.py 的 env_file=".env" 是相对路径，只找 cwd 下的 .env，找不到 backend/.env，于是回退到默认 DATABASE_URL=mysql+aiomysql://tryon:tryon@localhost:3306/tryon，连到 docker MySQL 容器 → Access denied（且 tryon 用户认证插件为 caching_sha2_password，aiomysql 不兼容）。
- backend/.env 实际配置是 SQLite（sqlite+aiosqlite:///./test.db）+ AI_ENGINE=mock，本应用本地跑。
- 修复：config.py 的 model_config.env_file 改为列表 [".env", <backend/.env 绝对路径>]（用 Path(__file__).resolve().parent.parent.parent / ".env"），无论运行目录都能加载 backend/.env。
- 验证：从根/backend 跑 get_settings() 均得到 sqlite；SQLite 建表 create_all 成功。
- 若用户后续要真用 docker MySQL：需确保 tryon 用户用 mysql_native_password（db/init/01-init.sql 已正确配置，但仅在 MySQL 数据卷为空时执行；若已初始化过需 docker compose down -v 重建卷，或手动 ALTER USER 'tryon'@'%' IDENTIFIED WITH mysql_native_password BY 'tryon'; FLUSH PRIVILEGES;）。

## 决策：全部改用 MySQL（用户明确"都用 mysql，全部改成 mysql"）
- backend/.env 的 DATABASE_URL 从 SQLite 改为 mysql+aiomysql://tryon:tryon@localhost:3306/tryon?charset=utf8mb4（保留 SQLite 兜底注释）。config.py 默认值本就是 MySQL，无需改默认值。
- docker-compose.yml db 服务加 MYSQL_DEFAULT_AUTHENTICATION_PLUGIN=mysql_native_password（aiomysql 0.2.0 不兼容 caching_sha2_password，否则 Access denied）。
- 验证：aiomysql 连 localhost:3306/tryon 仍 Access denied —— 因现有 mysql-data 卷是旧数据，init.sql 未重跑，tryon 用户仍是 caching_sha2_password。**需用户手动 docker compose down -v 重建卷**（破坏性，未自动执行），重跑 db/init/01-init.sql 创建 mysql_native_password 的 tryon 用户。
- 结论：代码/配置层面已全部切 MySQL；运行前提是重建 MySQL 数据卷。
