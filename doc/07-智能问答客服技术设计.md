# 智能问答客服技术设计文档

## 1. 需求分析

### 1.1 业务背景
基于到店顾客场景，提供智能搭配推荐和问答服务，帮助顾客快速找到合适的服装搭配。

### 1.2 核心需求

| 需求编号 | 需求描述 | 来源 |
|---------|---------|------|
| REQ-001 | 支持自然语言问答，理解顾客搭配需求 | 顾客咨询场景 |
| REQ-002 | 推荐范围仅限当前商家的服装库存 | 业务约束 |
| REQ-003 | 会话记忆有效期为6小时（到店场景） | 到店顾客时效 |
| REQ-004 | 支持多轮对话上下文 | 对话连贯性 |
| REQ-005 | 推荐结果可直接试穿 | 闭环体验 |
| REQ-006 | 支持用户反馈评分 | 质量优化 |

### 1.3 用户旅程

```
顾客到店 → 打开聊天 → 提问搭配需求 → 获取推荐 → 选择服装 → 试穿体验 → 完成购买
```

## 5. API 设计

### 5.1 接口列表

| API 路径 | HTTP 方法 | Controller | 功能描述 |
|----------|-----------|------------|---------|
| `/api/v1/qa/ask/` | POST | QAAskView | 提交问题，获取回答和推荐 |
| `/api/v1/qa/feedback/{log_id}/` | PUT | QAFeedbackView | 用户反馈评分 |
| `/api/v1/qa/history/` | GET | QAHistoryView | 查询会话问答历史 |

### 5.2 接口详细设计

#### 5.2.1 POST /api/v1/qa/ask/

**请求体：**

```json
{
    "question": "string (必填) - 用户问题",
    "session_id": "string (可选) - 会话ID，不传则自动生成"
}
```

**成功响应 (200)：**

```json
{
    "success": true,
    "code": 200,
    "message": "success",
    "data": {
        "answer": "string - AI回答内容",
        "recommendations": [
            {
                "uuid": "string - 服装UUID",
                "name": "string - 服装名称",
                "category": "string - 分类",
                "subcategory": "string - 子分类",
                "color": "string - 颜色",
                "image_url": "string - 图片URL",
                "price": "number - 价格"
            }
        ],
        "log_id": "string - 日志ID（用于反馈）",
        "session_id": "string - 会话ID"
    }
}
```

**失败响应 (400/500)：**

```json
{
    "success": false,
    "code": 400,
    "message": "错误信息"
}
```

#### 5.2.2 PUT /api/v1/qa/feedback/{log_id}/

**请求体：**

```json
{
    "score": "integer (必填) - 1-5分",
    "text": "string (可选) - 反馈文本"

```

**成功响应 (200)：**

```json
{
    "success": true,
    "code": 200,
    "message": "反馈已记录"
```

```json
            {
```

## 7. 核心业务逻辑

### 7.1 问答处理流程

```
用户提问 → 分析意图 → 提取偏好 → 查询服装库 → 生成推荐 → 调用LLM → 返回结果
              ↓                                      ↓
         意图分类：                            商家隔离过滤
         - recommendation                      merchant_id=当前商家
         - question
         - general
```

### 7.2 意图分析规则

| 意图类型 | 关键词 | 处理逻辑 |
|---------|--------|---------|
| recommendation | 搭配、推荐、配什么、穿什么、好看 | 调用推荐引擎 |
| question | 怎么、什么、为什么、如何、哪里 | 调用LLM直接回答 |
| general | 默认 | 调用LLM直接回答 |

### 7.3 推荐算法

```python
# 推荐优先级
1. 按用户偏好过滤 (preferred_categories, preferred_colors)
2. 按问题关键词匹配 (category, style)
3. 按销量/热度排序
4. 最多返回6件
```

## 8. 安全考虑

### 8.1 数据隔离

- 所有查询必须携带 `merchant_id`
- 禁止跨商家数据访问
- 会话数据按商家隔离

### 8.2 会话安全

- Session ID 使用 UUID 生成
- 会话自动过期（6小时）
- 支持手动清除会话

### 8.3 输入安全

- 对用户输入进行 XSS 过滤
- 限制输入长度（最大500字符）
- 过滤敏感词

### 8.4 日志脱敏

- 不记录用户身份信息
- 日志仅关联匿名会话ID
- 定期清理过期日志

## 11. 代码安全性

### 11.1 注意事项

| 风险点 | 描述 | 关联模块 |
|--------|------|---------|
| SQL 注入 | 通过拼接SQL获取数据 | 后端服务 |
| XSS 攻击 | 用户输入未过滤 | 前端组件 |
| 数据泄露 | 跨商家访问 | 后端API |
| 会话劫持 | Session ID 泄露 | 前后端 |

### 11.2 解决方案

| 风险点 | 解决方案 |
|--------|---------|
| SQL 注入 | 使用 ORM 查询，避免拼接 SQL |
| XSS 攻击 | 使用 React 自动转义，对富文本进行过滤 |
| 数据泄露 | 强制校验 merchant_id，权限中间件 |
| 会话劫持 | 使用 HTTPS，设置安全 Cookie |
