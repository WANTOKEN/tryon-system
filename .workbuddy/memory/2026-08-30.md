
## frontend-react safeStorage IndexedDB 报错修复
- 根因：App.jsx 引用了 STORAGE_KEYS.REUSE_AVATAR_KEY / REUSE_AVATAR_SOURCE / AVATAR_FILE，但 constants/storageKeys.js 未定义，取值为 undefined，传给 IDBObjectStore.get() 抛 DataError。
- 修复：storageKeys.js 补齐 tryon_reuse_avatar_key / tryon_reuse_avatar_source / tryon_avatar_file；safeStorage.js 的 setIDB/getIDB/removeIDB 增加 key 空值防御。
- 注意：此前"复用已上传图片 key"功能因 undefined key 从未生效过。

## 历史结果预览弹窗"+"不显示搭配 bug 修复
- 根因：后端 `backend/app/api/v1/tryon.py` 的 `_serialize_record` 把 `clothing` 输出成 FileRecord.uuid 字符串数组，但前端 HistoryModal/预览弹窗按对象数组取 `clothing_name/name` → 取 undefined → 历史图预览里"衣服搭配"完全不显示。
- 后端修复：新增 `_resolve_clothing(db, uuids)`，按 `Clothing.image_key.in_(uuids)` 联表取 name/category/thumb_url；未命中 Clothing 的 uuid 用 FileRecord 兜底取 access_url。已确认提交的 clothing_ids = item.image_key = FileRecord.uuid = Clothing.image_key，匹配正确。
- 前端修复：`App.jsx` 预览弹窗 `openPreviewModal` 增加 clothing 参数；新增 `previewShowOutfit` 状态，底部加"查看搭配"(+/-)开关按钮，展开后横向展示该结果使用的服装缩略图+名称。`HistoryModal` 两处 onPreview 传入 `record.clothing`。`useI18n.jsx` 补 viewOutfit/hideOutfit/unnamed 三语。
- 影响面：前端仅 HistoryModal 与 useTryOn 消费 record.clothing，改对象数组均兼容。
